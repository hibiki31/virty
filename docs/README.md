作業開始時はこのファイルを読み、必要な文書だけを参照する。

| 文書 | 内容 | 読むタイミング |
|---|---|---|
| [requirements.md](requirements.md) | 利用目的、機能要件、完成条件 | 仕様・UI・機能を変更するとき |


## 更新ルール

- 要件変更は`requirements.md`、構成や責務の変更は`architecture.md`へ記録する。
- 開発・運用手順の変更は`development.md`へ記録する。
- 実装コード、OpenAPI、migration、Git履歴で確認できる詳細は重複記載しない。
- 作業完了時はdocsを実装内容に合わせて更新し、コードと一緒にコミットする。
